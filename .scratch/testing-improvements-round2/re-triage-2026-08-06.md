# Round-2 backlog re-triage — 2026-08-06

The 82 issues still in `issues/open/` were filed on **2026-07-28**. Between then and now the
foundation-hardening campaign ran to completion: four core areas extracted into their own crates
(`frogdb-txn`/`frogdb-vll`, `frogdb-recovery`/`frogdb-persistence`,
`frogdb-replication`/`frogdb-replication-runtime`, `frogdb-cluster`/`frogdb-cluster-runtime`),
246 `FM-<AREA>-NNN` failure-mode rows written and lint-enforced against their forcing tests,
mutation gates set on all eight locked crates, and a long tail of bug fixes landed. The
redis-regression compat suite was unfrozen at campaign exit.

This document re-baselines every open issue against the current tree. It is triage only — no
production code was changed.

## Method

Per issue: read the claims and their `file:line` evidence, locate the cited code on today's tree
(much of it moved during the extractions — a missing file is usually a move), check whether an
FM row plus a named forcing test now covers the behavior, and assign one verdict. Verification
was static (read + `rg` + `git log -S`) except for issue 90, where the two live-bug claims were
settled by running targeted tests.

Every issue file carries a `## Re-triage 2026-08-06` section with its verdict and evidence.
`fixed` and `superseded` issues had their `Status:` flipped to `done` and were moved into
`issues/done/`; `still-valid` and `partially-fixed` stayed in `issues/open/`.

## Cross-cutting observations

These came out of the sweep and are worth more than any single verdict.

1. **Three tests named as `Forced by` witnesses in LOCKED failure-mode specs assert nothing.**
   `crash_recovery_tests.rs:701`/`:735` (`// FM-PERSISTENCE-017`) is
   `assert!(result.is_ok() || result.is_err())`; `cluster/src/storage.rs:656`
   (`// FM-CLUSTER-017`) never reads `committed` back; `cluster/src/network.rs:891`
   (`// FM-CLUSTER-051`) asserts only an enum discriminant. `just lint-spec` enforces
   that a row names a test and a test names a row — it cannot enforce that the test *asserts*
   anything. The specs currently claim coverage these tests do not provide.

2. **Two failure-mode spec cells are factually wrong today.** `FM-PERSISTENCE-033`'s Invariant
   says "only a `RocksError` from the iteration itself propagates" — it does not (issue 42).
   `FM-PERSISTENCE-019`'s Observable says the restored checkpoint contains "search-index state" —
   it does not; Phase 2 even added `test_stager_excludes_search_sidecar` pinning the opposite
   (issue 46).

3. **A mutation-gated lock is not blanket cover for its area.** Three independent instances:
   issue 50's missing VLL gate lives in `crates/core`, which neither the txn nor the vll spec
   reaches; `frogdb-vll` is at 100% yet `vll-failure-modes.md` has only 4 rows (all on the
   continuation lock, with the scatter phases explicitly unrowed), so 14 of issue 88's 15
   findings survive the lock; and issue 73's fsync gap sits inside locked `frogdb-cluster` with
   no row naming it. The score measures the rows you wrote, not the area.

4. **The coverage pipeline is manufacturing work items.** Issue 94's headline evidence
   (`ShardSearchIndex::open_in_ram` "untested at 0/41 regions") was false — it had 15 in-crate
   callers when filed. Same for issue 79/F6 and issues 83/F5 and 83/F11, where the audit's
   exclusion-header scan over `redis-regression` produced false "untested" claims against tests
   that had existed for months. Issues 27/28 are therefore not just tooling debt; they are
   actively generating bad backlog. This is fresh evidence for decision 31 (D3).

5. **`lint-clock-seam` has a hole.** `scripts/clock-seam.py`'s regexes require `::now()` with
   parentheses, so the function-reference form slips through: `acl/src/ratelimit.rs:20`
   (`get_or_init(Instant::now)`) and `persistence/src/snapshot/rocks_coordinator.rs:289`
   (`unwrap_or_else(SystemTime::now)`) — the latter inside a mutation-gated locked crate. Under
   turmoil both read a different timeline than the rest of the server, which is exactly what the
   gate exists to prevent. Fixing the regex plus those two sites also closes issue 03's residue.

6. **Two audit asks were already satisfied when they were filed.** The `ClusterWriter` seam
   (`1dfd57c0`, 2026-07-22) and the asymmetric-partition scenario (`98495716`, 2026-07-23) both
   predate the 2026-07-28 audit that requested them (issues 14 and 13).

7. **Issue 90's blockers have dissolved.** Issue 18 is done (F3/F5 fixed), the clock seam exists
   (F14 drops from "Effort 3" to level 1–2), and the promoted-node PSYNC entry is unblocked —
   `new_replication_id` now has a production caller (`primary/mod.rs:385`) and the PRD reads
   `Status: implemented`. Its `Depends on` list should be pruned.

8. **Supersessions concentrated two defects into two theme issues.** Issues 56 → 25 and 61 → 23.
   Both survivors are now load-bearing for defects with no issue file of their own, and both
   annotations say so explicitly. Do not close 23 or 25 as "just a test gap".
